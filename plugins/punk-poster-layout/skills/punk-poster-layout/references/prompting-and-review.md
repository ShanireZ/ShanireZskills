# 构图提示与验收

## 六个结构变量

在写风格词以前，先把以下关系写清楚：

- 焦点：观众第一眼看哪里。
- 层级：标题、主视觉、日期、说明和 CTA 谁先谁后。
- 分组：哪些内容应被理解为同一组。
- 平衡：左右、上下的视觉重量如何稳定或有意失衡。
- 动势：视线沿直线、斜线、曲线、环形还是模块移动。
- 空间：哪里留白，哪里密集，边缘安全区在哪里。

尺寸、颜色、对比、对齐和留白影响阅读顺序；相近、相似和连续帮助观众自动分组。不要只给模型一个构图名，把这些变量变成位置、比例和路径。

## 通用结构提示

适合 01–16，或任何以焦点和路径为主的海报：

```text
制作一张【比例】海报，主题为【主题】。
采用【构图名称】；主视觉【对象】位于【位置】，约占画面【比例】；
视线从【入口】沿【路径】移动到【终点】；
标题“【主标题】”为一级信息，【副标题 / 日期 / CTA】依次为二、三级；
使用【留白策略】、【字体语气】、【色彩和材质】；
保持清晰对齐与边缘安全区；
避免【多焦点 / 随机文字 / 过度装饰 / 错误裁切】。
```

第一版只写一个主构图，再补一个辅助关系。例如：

```text
主构图使用三分法，辅助使用 S 型曲线；
产品落在右上三分交点，标题沿左侧三分线对齐，三处辅助信息沿隐性 S 曲线连接。
```

## 网格与构图的关系

构图决定观众先看哪里、沿什么路径阅读；Grid System 负责对齐、比例、间距和复用。海报可以同时有两层控制：观众感受到的分屏、满版、叠字或拼贴，以及设计师用来对齐的纵栏、横行、模块、基线和沟槽。

不要只写“使用网格系统”。指定栏数、行数、沟槽、跨度、共享边线和受控破格，例如：`六栏网格，24px 沟槽，标题跨四栏，图片跨三栏，日期占一栏`。这些数值是可调起点，不是固定规范。

### 给图像模型的网格模板

```text
制作一张【画幅比例】海报，主题为【主题】。
主构图采用【17–32 中的一种构图】；
建立【栏数】栏 ×【行数】行的隐形模块网格，沟槽一致；
主标题“【标题】”跨【几栏 × 几行】，主视觉【对象】跨【几栏 × 几行】；
日期、说明和 CTA 分别占【模块位置】，共享【左边线 / 基线 / 边距】；
视线从【入口】沿【路径】移动到【终点】；
允许【少量相关的受控破格，通常由一个主破格元素或焦点簇承担】，其余内容严格归位；
使用【色彩】与【字体语气】，保留【留白策略】；
避免随机跨栏、多个焦点、错误裁切、文字乱码和辅助线全部可见。
```

图像模型把栏和模块当软约束。目标是稳定结构与视觉趋势，不要声称它能像浏览器一样保证像素级落位。

### 给 HTML/CSS 的网格模板

```text
创建一个 aspect-ratio:【比例】的海报组件。
外层使用 CSS Grid：
grid-template-columns: repeat(【栏数】, 1fr);
grid-template-rows: repeat(【行数】, 1fr);
gap: clamp(【最小沟槽】, 【响应值】, 【最大沟槽】);
主标题放在 grid-area:【位置】，主视觉放在 grid-area:【位置】，
元信息共用一条左对齐线和统一间距 token；
图片使用 object-fit:cover，并通过 object-position 锁定裁切焦点；
只允许【指定的主破格元素或相关焦点簇】跨线或错位，其余元素严格对齐网格；
提供可开关的调试网格覆盖层；
在移动端保持构图关系，不要直接退化成所有内容单列堆叠。
```

如果先用图像提示寻找视觉方向，再用 HTML 重建，两个输出必须共享同一份结构描述：相同的栏数、跨度、焦点、层级、边距和阅读路径。

## 图像提示的完成标准

把结构词融入完整提示，而不是在末尾堆关键词。成品提示至少交代：

1. 画幅和用途；
2. 主构图及辅助关系；
3. 主视觉的位置、比例和裁切；
4. 标题、辅文、日期、地点、CTA 的层级；
5. 入口、路径和终点；
6. 对齐、留白、色彩、字体与材质；
7. 安全区和负面约束。

提示中的事实文案必须逐字来自用户或权威 brief，不得补写标题、日期、地点、票务或品牌标识。长标题只有在用户允许时才能提炼；否则保留原文，并避免让图像和标题同时争夺第一焦点。

当文字必须逐字准确时，优先让图像模型生成无字或少字底图，再用 HTML/CSS 或后期排版叠加真实文本。如果用户坚持一次成图，明确说明模型文字不保证准确；生成后必须把实际产物与原文逐字核验，发现差异就如实报告，不能把提示词中的正确文案当作产物已通过。

## HTML/CSS 的完成标准

- 使用 Grid 或 Flexbox 表达主结构，绝对定位只处理明确的叠层、路径节点或受控破格。
- 用 CSS 自定义属性保存比例、沟槽、边距、字号、颜色和层级 token。
- 用 `object-fit:cover` 和 `object-position` 管理跨尺寸裁切焦点。
- 语义 DOM 顺序必须与预期阅读顺序一致；不要用 CSS 视觉排序制造相反的可访问顺序。
- 每段文本只保留一个可访问副本；图上叠字需要显式的前景文字、图像、背景文字层，装饰副本加 `aria-hidden="true"`。
- 有意义的图片提供准确 `alt`；纯装饰图片使用空 `alt` 或 `aria-hidden="true"`。
- 导航型 CTA 使用链接，触发界面动作的 CTA 使用按钮；两者都保留清晰的 `:focus-visible` 状态。
- 调试覆盖层可开关，发布状态默认关闭。
- 响应式变化保留相同语义关系与层级，但不强制保持同一几何。只有在最小字号、最小单元宽度、裁切与交互尺寸仍满足时才保留原列数或并排关系；否则允许有依据地重排。
- 实际测试窄屏与 200% 缩放；确认文本、焦点顺序、CTA、裁切和内容关系仍可用。
- 关键文本保持足够对比；密集与满版构图可用局部实色底、局部渐变或 outline，不要把整张图统一压暗。

## 交付前预检：提示与规格

推荐、提示词或尚未渲染的 HTML/CSS 规格只能做 preflight/spec lint：检查必需事实是否原样保留、主构图与辅助关系是否冲突、位置/比例/路径/安全区是否具体、负面约束是否完整，以及数值是否被明确标为可调起点。

没有实际产物时，不得声称裁切、响应式、对比或可读性已经通过；在交付中把这些项目写为 `not tested`。静态代码检查通过也不等于浏览器 viewport 已验收。

## 产物验收（必须有实际产物）

只有拿到实际生成图、渲染页面或截图，以及目标画幅、viewport 或输出尺寸后，才运行本节。缺少产物或目标 viewport/尺寸时停止 review 并请求补充。review 默认只报告看得到或实际测到的证据，并提出可测量的修正，不修改产物；只有用户明确要求“审查并修复”时，才在先报告诊断后修改已明确识别的产物并重跑相关检查。单独的 review 请求不构成修复授权。

按顺序检查，发现问题时先改结构参数，不要继续追加模糊风格词。

1. 入口存在吗？缩成手机信息流大小，第一眼还能找到标题或主视觉。
2. 三层信息分得出来吗？标题、主视觉和辅助信息具有明显尺度或对比差。
3. 主次比例清楚吗？`60/40`、`70/30` 或跨栏数量能够解释视觉重量。
4. 共同边线稳定吗？标题、图片、日期和说明至少共享一到两条对齐线。
5. 留白和沟槽在帮助阅读吗？同层间距重复，留白用于隔离或强调，而不是单纯空缺。
6. 破格数量受控吗？通常由一个主破格元素或相关焦点簇承担；标题与主视觉若各自破格，必须服务同一层级。
7. 图文层级明确吗？图上叠字能够判断字在前、字在后或与主体穿插。
8. 裁切焦点安全吗？脸、手、产品标志、标题关键笔画、日期和 CTA 未被误切。
9. 路径有效吗？斜线、曲线、环或分屏把视线带向有效信息而非画外。
10. HTML 能响应吗？实际改变容器宽度并测试 200% 缩放后，语义关系、层级、可读性和焦点顺序继续成立；不要求保持同一几何。
11. HTML 可访问吗？DOM 阅读顺序正确，文本只有一个可访问副本，图片替代文本、CTA 语义与可见焦点都与产物一致。

## 可靠默认值

- 不确定且内容中等时：先试 03 三分法。
- 标题、图片、数据和说明同时存在时：先试 21 模块网格，把 4×6 作为可调起点，让约 80% 的元素归位，再选择一个主破格标题。
- 对比双对象时：优先 16 左右分屏，默认从 60/40 而不是 50/50 开始。
- 图像 + 说明时：优先 17 上下分屏，默认从 62/38 开始。
- 安静、高端、信息很少时：优先 05 大留白单点，保留 65%–80% 主动留白。
- 实验构图时：先建立一个可识别规则，再使用少量相关的受控破格，通常由一个主破格元素或焦点簇承担。
